h1. PRD：Binding Account 啟用／停用

p. *版本*：v1（2026-08-14）　*類型*：功能變更　*負責*：PM
p. *Mockup*："Interactive mockup":https://guswei.github.io/betally-bo-mockup/binding-account-status/mockup.html （右上可切換「顯示 RD 註記」與權限開關）
p. *相關*："RD Spec":https://github.com/guswei/betally-bo-mockup/blob/main/binding-account-status/binding_account_status_spec.md

h2. 1. 需求背景

p. GCP Agent BO 的綁定帳號目前只有新增與刪除兩種操作。客服要暫時停掉一個玩家的收款帳號時，只能整筆刪除，之後要用再重建一次，該帳號的歷史資料也跟著消失。客戶希望有更彈性的管理方式，不必為了暫停而永久刪除資料。

p. 受影響的對象是使用 @2.1 Player List@ 管理玩家收款帳號的 BO 操作人員，以及會員端提款頁面的玩家。

p. 本案為綁定帳號加上啟用與停用兩種操作，並把唯一性約束延伸到停用中的資料，讓停用的帳號不會被其他玩家搶走。本案不改動提款流程本身，也不改動玩家層級的封鎖功能。

h2. 2. 核心功能變更

|_. # |_. 變更 (FR) |_. 說明 |
| FR-1 | 新增綁定帳號狀態欄位 | 綁定帳號新增 @status@ 欄位，值為 @ACTIVE@ 或 @INACTIVE@，預設 @ACTIVE@。清單最後一欄顯示該狀態。 |
| FR-2 | 新增停用操作 | @ACTIVE@ 的綁定帳號可停用。停用後仍留在 BO 清單並顯示 @Inactive@，不出現在會員端。提款建立 API 須在後端驗證帳號 @status@，非 @ACTIVE@ 時拒絕建立提款單。前端過濾與後端驗證兩層都要做。 |
| FR-3 | 新增啟用操作 | @INACTIVE@ 的綁定帳號可啟用。啟用後恢復顯示於會員端，玩家可照常使用。 |
| FR-4 | 唯一性約束涵蓋停用資料 | 停用中的綁定帳號繼續佔用其自然鍵，其他玩家無法用同一組銀行帳號、錢包位址或手機號碼註冊。同一玩家重新新增自己已停用的帳號同樣被擋，引導改用啟用。 |
| FR-5 | 停用的兩個阻擋條件 | 預設帳號不可停用；有處理中提款單的綁定帳號不可停用。兩者前端與後端都要擋。 |
| FR-6 | 刪除加二次確認 | 既有刪除動作新增二次確認，文案須說明刪除後該帳號可被其他玩家註冊，並引導改用停用。刪除的權限與行為維持現狀。 |
| FR-7 | 新增狀態篩選 | 清單篩選區新增 @Status@ 下拉，選項 @ALL@ / @Active@ / @Inactive@，預設 @ALL@。 |

p. 範圍：IN — @2.1 Player List@ → @Player's Info@ → @Binding Account@ 分頁；綁定帳號資料表；會員端提款帳號選單；提款建立時的帳號資格驗證。OUT — 提款的審批、派單、退款與狀態流轉、玩家層級 @Block@、@Edit@ 對話框既有欄位、@Delete@ 的權限、批次啟用與批次停用、既有已刪除資料的回補。

h2. 3. 介面設計

p. 以 Mockup 為準："https://guswei.github.io/betally-bo-mockup/binding-account-status/mockup.html":https://guswei.github.io/betally-bo-mockup/binding-account-status/mockup.html 。重點：

* @Binding Account@ 清單最後一欄新增 @Status@，@ACTIVE@ 顯示綠底 @Active@，@INACTIVE@ 顯示灰底 @Inactive@ 且整列灰階。既有欄位順序不動。
* @Actions@ 欄：@ACTIVE@ 的列出現 @Deactivate@，@INACTIVE@ 的列出現 @Activate@，兩者互斥。既有編輯與刪除圖示位置不動。
* 預設帳號與有處理中提款單的列，@Deactivate@ 呈 @disabled@ 並附說明文字。權限不足時按鈕直接隱藏。
* 停用與啟用對話框說明操作後果，不需勾選式確認。刪除對話框需勾選確認框才能送出。
* 新增綁定帳號撞唯一鍵時，撞到同一玩家自己的停用資料則引導改用啟用；撞到其他玩家的資料只回一般性訊息。

p. *BO 欄位表*：

|_. 欄位 |_. 型別/精度 |_. 必填 |_. 說明 / enum / 邊界 |
| @status@ | @enum('ACTIVE','INACTIVE')@ | 是 | 綁定帳號啟用狀態。@NOT NULL@，預設 @ACTIVE@。雙向可切換，無終態。前端顯示徽章，後端為真值來源。 |
| @Status@（篩選） | @enum('ALL','ACTIVE','INACTIVE')@ | 否 | 清單篩選條件，預設 @ALL@。純查詢條件，不寫入資料。 |

h2. 4. 資料模型

p. 綁定帳號資料表新增一個欄位並調整唯一索引範圍。既有欄位不變更型別或約束。

|_. Table |_. 欄位 |_. 型別 |_. 約束 |
| 綁定帳號表 | @status@ | @enum('ACTIVE','INACTIVE')@ | NOT NULL，DEFAULT @ACTIVE@ |
| 綁定帳號表 | 自然鍵組合 | 依 @Binding Type@ 而異 | UNIQUE，涵蓋 @INACTIVE@ 的資料列 |

p. 自然鍵組合：Bank Card 為銀行 ＋ 銀行帳號；E-Wallet 為錢包位址；Pulsa 為手機號碼。

p. 唯一索引為全表唯一，不使用條件式索引。同一玩家重新新增自己已停用的帳號同樣撞鍵，因此不需要排除自身停用列的例外邏輯。

p. Migration 方向：所有現存綁定帳號一律填入 @ACTIVE@。刪除仍會移除資料列並釋放自然鍵。

h2. 5. 流程圖

p. 綁定帳號的狀態轉換與停用時的兩個阻擋條件。

<pre>
flowchart TD
  A[BO 操作員在 Binding Account 清單選一筆] --> B{該筆 status}
  B -->|ACTIVE| C{是預設帳號?}
  B -->|INACTIVE| H[顯示 Activate]
  C -->|是| D[Deactivate disabled<br/>提示先變更預設]
  C -->|否| E{有處理中提款單?}
  E -->|是| F[後端回 409<br/>提示有處理中的單]
  E -->|否| G[停用成功<br/>status 改 INACTIVE<br/>自然鍵仍被佔用<br/>會員端不再顯示]
  H --> I[啟用成功<br/>status 改 ACTIVE<br/>會員端恢復顯示<br/>Default Value 不變]
  G --> H
  I --> C
</pre>

h2. 6. 選單位置

p. 沿用現有，無新增選單項。功能位於既有頁面內。

|_. 選單路徑 |_. 角色 / 權限 |_. 說明 |
| @2.1 Player List@ → @Player's Info@ → @Binding Account@ | 被授予「綁定帳號狀態管理」權限者 | 可執行 Activate 與 Deactivate。不綁定 4-tier 層級，由後台權限設定控制 |
| 同上 | 未被授予該權限者 | 唯讀。Activate 與 Deactivate 按鈕隱藏，不以 @disabled@ 呈現 |
| 同上 | 既有可刪除者 | @Delete@ 權限維持現狀，不因本案調整 |

h2. 7. 驗收標準（AC）

|_. AC-ID |_. 對應 FR |_. 驗收條件 |
| AC-01 | FR-1 | 既有綁定帳號經 migration 後，@status@ 皆為 @ACTIVE@，清單最後一欄顯示 @Active@。 |
| AC-02 | FR-1 | 清單顯示 @INACTIVE@ 的列時，狀態徽章為 @Inactive@ 且該列以灰階呈現。 |
| AC-03 | FR-2 | 對一筆非預設、無處理中提款單的 @ACTIVE@ 綁定帳號執行停用，該筆 @status@ 變為 @INACTIVE@ 且仍出現在 BO 清單。 |
| AC-04 | FR-2 | 綁定帳號停用後，該筆不出現在會員端提款帳號選單。 |
| AC-05（負向） | FR-2 | 綁定帳號停用後，玩家*不得*使用該帳號送出提款申請。 |
| AC-06 | FR-3 | 對一筆 @INACTIVE@ 綁定帳號執行啟用，該筆 @status@ 變為 @ACTIVE@ 且恢復出現在會員端提款帳號選單。 |
| AC-07 | FR-3 | 啟用一筆綁定帳號後，其 @Default Value@ 維持啟用前的值，不自動變更為預設。 |
| AC-08 | FR-4 | 玩家 A 有一筆 @INACTIVE@ 的銀行帳號，玩家 B 用同一組銀行與帳號新增綁定帳號時被擋下。 |
| AC-09（負向） | FR-4 | 承 AC-08，回給玩家 B 的錯誤訊息*不得*包含玩家 A 的任何識別資訊。 |
| AC-10 | FR-4 | 同一玩家新增自己已停用的綁定帳號時被擋下，訊息指出該帳號已存在且為停用中並引導改用啟用。 |
| AC-11（負向） | FR-5 | 對 @Default Value = true@ 的綁定帳號送出停用請求，後端*不得*變更其 @status@，並回 @409@。 |
| AC-12（負向） | FR-5 | 對有處理中提款單的綁定帳號送出停用請求，後端*不得*變更其 @status@，並回 @409@。 |
| AC-13 | FR-5 | AC-11 與 AC-12 的兩個 @409@ 使用不同的錯誤代碼或訊息鍵，前端可據以顯示不同原因。 |
| AC-14 | FR-6 | 點擊刪除時出現二次確認對話框，未勾選確認框前送出按鈕不可點擊。 |
| AC-15 | FR-6 | 刪除對話框文案包含「刪除後該帳號可被其他玩家註冊」與「若只是暫停使用請改用停用」兩項資訊。 |
| AC-16 | FR-6 | 刪除一筆綁定帳號後，其他玩家可用同一組帳號資料成功新增綁定帳號。 |
| AC-17 | FR-7 | @Status@ 篩選選 @Inactive@ 時，清單只列出 @status = INACTIVE@ 的綁定帳號；預設 @ALL@ 時停用與啟用的資料都列出。 |
| AC-18（負向） | FR-2、FR-3 | 未被授予「綁定帳號狀態管理」權限的操作者登入時，清單*不得*出現 @Activate@ 與 @Deactivate@ 按鈕；直接呼叫對應 API 時後端回 @403@ 且*不得*變更資料。此判定與該操作者的 4-tier 層級無關。 |
| AC-19 | FR-2、FR-3 | 每次啟用或停用皆產生一筆異動紀錄，內容包含操作者、時間、對象綁定帳號、變更前的值與變更後的值。 |
| AC-20（負向） | FR-2 | 直接呼叫提款建立 API 並指定一筆 @status = INACTIVE@ 的綁定帳號時，後端*不得*建立提款單，回 @409@ 且錯誤鍵為 @BINDING_ACCOUNT_INACTIVE@。 |
| AC-21（負向） | FR-4 | 同一支手機號以 @+62@ 開頭與以 @0@ 開頭兩種格式新增綁定帳號時，第二筆*不得*建立成功。銀行帳號含空白或連字號的變形寫法同理。 |
| AC-22（負向） | FR-5 | 停用檢查與提款單建立同時發生時，*不得*出現處理中的提款單掛在 @status = INACTIVE@ 帳號上的結果。 |

h2. 8. 非功能需求（NFR）

|_. NFR-ID |_. 類別 |_. 需求 |
| NFR-REL | 可靠性 | 新增 @status@ 欄位與唯一索引調整不得影響既有綁定帳號的新增、編輯、刪除與查詢。既有提款流程的行為不得因本案改變。停用中的綁定帳號不得被會員端取得。 |
| NFR-DATA | 金額/資料精度 | 本案不新增金額欄位。既有提款金額欄位維持 @DECIMAL(18,2)@，本案不變更其精度，亦不得改用浮點數。@status@ 為 @enum@，不得以自由字串儲存。 |

h2. 9. 假設與限制（ASM / CST）

|_. ID |_. 內容 |
| ASM-1 | 會員端提款帳號選單需同步過濾 @status = ACTIVE@（前端層）。此項需 FE 團隊實作，非 BO 單邊可完成。後端層的提款建立驗證（AC-20）不依賴 FE 進度，兩者可分別上線。 |
| ASM-7 | 建立唯一索引前需盤查既有重複資料。既有資料表沒有此約束，可能已存在同一自然鍵的多筆資料，需 RD 於部署前確認並提供重複清單。 |
| ASM-8 | 自然鍵正規化規則（手機號國碼格式、銀行帳號去空白、錢包位址大小寫）需 RD 依實際資料現況確認，特別是既有資料中已存在的格式變形。 |
| ASM-2 | @Player's Info@ 已有 @Update History@ 分頁。若其機制已涵蓋綁定帳號異動則沿用為 AC-19 的落點，未涵蓋則另建紀錄。需 RD 確認現況。 |
| ASM-3 | 新增的「綁定帳號狀態管理」權限節點在既有權限設定畫面的名稱與擺放位置，需 RD 依既有權限設定結構決定。 |
| ASM-6 | 「處理中的提款單」的判定範圍以既有提款狀態機為準，需 RD 確認哪些狀態算處理中。 |
| CST-1 | 刪除的權限與行為維持現狀，本案只加二次確認，不得順手收緊權限。 |
| CST-2 | 不引入 @Verify Status@ 與 @Blocked@。綁定帳號的狀態只有 @ACTIVE@ 與 @INACTIVE@ 兩個值。 |
| CST-3 | 不動玩家層級的 @Block@ 功能，該功能與綁定帳號狀態屬不同軸。 |
| CST-4 | 唯一性約束涵蓋停用資料後，刪除仍會釋放自然鍵。此為需求方知情後保留的路徑，以二次確認的文案提示處理，不以權限封鎖。 |
| CST-5 | 既有已刪除的綁定帳號不回補佔位。這些帳號的自然鍵維持可用，其他玩家可以註冊（需求方 2026-08-14 拍板）。 |

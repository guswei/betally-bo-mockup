新增一列：Payment Account Transactions，排在 Free Spin Report 之後。選項 Enable／Deny，型別是布林值，每個 Agent 各自一個設定。版面、儲存方式、右側 updated : 的顯示內容與格式、變更紀錄，都與既有的兩列相同。儲存方式（現況行為）：選項改變後，該列的選項右邊出現 SAVE 按鈕，按了才儲存；沒按 SAVE 就離開，設定不變。DEMO：選回原本已儲存的值時 SAVE 按鈕消失、儲存後顯示 Saved 提示、updated : 後面接操作人與時間，這三點是示意，實際照既有兩列的行為。
預設值：Deny。功能上線時所有既有的 Agent 都是 Deny；之後新建的 Agent 也是 Deny。
控制的對象：這個 Agent 的 Agent BO 能不能使用 3.11 Payment Account Transactions。
・Enable：Agent BO 的 11.2 Role Setting 在 Payment Management 底下出現群組 Payment Account Transactions 與它的五個權限節點（VIEW、EXPORT、Internal Transfer、External Transfer、Adjust Balance）。五個節點預設都不勾，由 Agent 自己開給角色；有勾 VIEW 的角色才看得到選單。
・Deny：Agent BO 的 11.2 Role Setting 不顯示群組 Payment Account Transactions 與它的節點；所有帳號（含最高權限帳號）的選單都不顯示 3.11；3.7 列表不顯示 Transactions 按鈕；直接輸入網址時依既有的無權限處理。
前端＋後端都要擋：Deny 的 Agent 呼叫 3.11 的任何介面（交易紀錄查詢、每帳號合計、摘要卡、帳號下拉選項、匯出、三種手動單）一律回 403，不可只靠隱藏選單。
由 Enable 改成 Deny：按 SAVE 後立即生效，已登入的使用者下一次操作就被擋下。角色原本勾選的五個節點保留不清除，但不生效；之後改回 Enable，原本的勾選恢復生效。帳號的餘額與交易紀錄都保留。
Deny 期間的資料：玩家存款核准、指定帳號的出款核准仍照常產生交易紀錄並變動餘額（Agent BO 開發 Spec 第 4 節），只是這個 Agent 看不到 3.11。
誰能操作：能在 Admin BO 編輯 Agent List 的人，沿用這一頁既有的權限，不新增 Admin BO 的權限節點。
範圍：這個開關只控制 3.11。3.2 核准對話框的 Payment Account 選項、3.7 的新欄位（出款設定、餘額、代碼與分組）不受它控制，所有 Agent 上線後都看得到。Deny 不改變核准時指定帳號清單的條件：照樣依帳號目前的出款設定、餘額與每日門檻判定，不看餘額是怎麼來的。
介面欄位：這一頁既有的讀取與儲存增加一個布林欄位（true＝Enable，false＝Deny），讀取時回傳已儲存的值與 updated : 要顯示的資料；Agent BO 判斷 403 與要不要顯示節點，讀的是同一個設定。

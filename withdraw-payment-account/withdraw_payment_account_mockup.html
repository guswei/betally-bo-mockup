Allow Deposit：必填，Yes／No。新增帳號預設 Yes；既有帳號上線時為 Yes。只有 BANK-OFFLINE 的帳號可以改成 No；其他通道的帳號固定為 Yes 且不可改，並顯示 Only available for BANK-OFFLINE accounts.，存款行為與現況相同。前端＋後端都要擋。No 時這個帳號不會派給玩家存款；既有規則「通道底下沒有可用的收款帳號時，前台不顯示該存款通道」判斷時，把 Allow Deposit = No 的帳號視為不可用。既有存款欄位的必填與驗證都不變。
Allow Withdraw：必填，Yes／No。代表能不能從這個帳號轉出錢：Yes 時這個帳號才會出現在出款核准的帳號清單，也才能在 3.11 做 Internal Transfer 的轉出與 External Transfer。新增 BANK-OFFLINE 的帳號預設 Yes；既有帳號上線時為 No。
只有 BANK-OFFLINE 的帳號能出款：Payment Channel 不是 BANK-OFFLINE 時，Allow Withdraw 固定為 No 且不可改，並顯示 Only available for BANK-OFFLINE accounts.；在新增頁把通道改選成其他通道時立即變成 No。前端＋後端都要擋。
通道不可搬移NEW：帳號是不是 BANK-OFFLINE 帳號，在新增時決定，之後不變。編輯頁：BANK-OFFLINE 帳號的 Payment Channel 唯讀；其他通道的帳號，選項不含 BANK-OFFLINE，在其他通道之間改選與現況相同。新增頁可以選任何通道。編輯請求把帳號改進或改出 BANK-OFFLINE 時，後端回 400 PAYMENT_CHANNEL_NOT_CHANGEABLE，前端顯示 Payment Channel cannot be changed to or from BANK-OFFLINE.（mockup 不呈現）。前端＋後端都要擋。
Withdraw Threshold：DECIMAL(18,2)，金額禁用 float。Allow Withdraw = Yes 時必填、必須大於 0、最多兩位小數、不得大於 9999999999999999.99；單位是 BO 幣別的金額。Allow Withdraw = No 時不可編輯、不驗證，已存的值保留。前端＋後端都要擋。
Today Withdraw Amount：唯讀，今日從這個帳號轉出的金額合計，包含以這個帳號核准的玩家出款、INTERNAL OUT、EXTERNAL OUT，顯示方式與既有的 Today Deposit Amount 相同。新增與編輯的請求都不接受這個值。既有的 Today Deposit Amount 另外計入 INTERNAL IN。
Allow Withdraw Over Threshold：Allow Withdraw = Yes 時必填，預設 No。Yes＝今日累計未達門檻即可選，最後一筆可以讓累計超過；No＝今日累計加上該筆金額不得超過門檻。
修改門檻：今日已有累計後把門檻調低，或把 Allow Withdraw Over Threshold 由 Yes 改成 No，已有的累計不扣回；之後的核准依新設定判定。
BalanceNEW：唯讀，DECIMAL(18,2)。新增與編輯的請求都不接受這個值。只有 BANK-OFFLINE 的帳號有餘額，新增帳號與既有帳號上線時都是 0；其他通道的帳號顯示 -，系統不記錄它們的餘額。
Balance 的算法：功能上線之後，所有計入這個帳號的交易加總。加項：收款到這個帳號的玩家存款、INTERNAL IN、ADJUST IN；減項：以這個帳號核准的玩家出款、INTERNAL OUT、EXTERNAL OUT、ADJUST OUT。功能上線之前的存款與出款都不計入。
登記帳號實際有多少錢：不在這一頁。到 3.11 的 Adjust Balance 選 Set balance to，填帳號的實際金額，系統會把餘額對齊到那個數字。出款只看餘額夠不夠，沒有「必須先登記」這個條件：餘額不足的帳號不會出現在出款核准的帳號清單，也不能手動轉出；餘額除了來自登記，也會因玩家存款與內部轉入而增加。
Account Code、Account GroupNEW：兩個選填的文字欄位，只是方便客戶管理帳號的標記，兩者互相獨立；不填不影響出款核准、餘額、交易紀錄與手動單。各最長 32 字，只有 BANK-OFFLINE 帳號可以填，其他通道的帳號不可編輯且為空。Account Code 是客戶自己稱呼帳號用的代碼，不檢查是否重複；Account Group 是帳號的分組，例如帳號是從哪一個供應商取得的；不填就是沒有分組，畫面顯示 -。輸入時下方提示目前已有的分組，可以直接點選，也可以輸入新的。儲存時去掉前後空白；與既有分組只差大小寫時，沿用既有分組的寫法，不另成一組。分組沒有另外的管理清單，改名要逐一修改帳號。編輯頁排在 Balance 之後、Payment Level 之前；列表是第 36、37 欄。有代碼的帳號，系統裡所有顯示帳號的地方都在最前面加上代碼（格式 {Account Code} - {Bank Name} / {Account Name} / {Account No}），所有找帳號的搜尋也比對代碼。列表篩選區多兩個條件：Account Code（部分比對，不分大小寫）與 Account Group（下拉，預設 Account Group: All；選項是 No Group 加上目前所有 BANK-OFFLINE 帳號用到的分組，依名稱排序；No Group 找出沒有分組的帳號；選了任何分組時，其他通道的帳號不列出）。
變更紀錄：六個可編輯的新欄位，與既有欄位一樣寫入 11.9 Change Log。餘額的每一次變動都記在 3.11。
權限：檢視與編輯沿用 3.7 Payment Account 既有的權限，這一頁不新增權限節點。
新頁面：選單位置在 3. Payment Management 底下、3.10 Manual Balance Adjustment 之後。這一頁是 BANK-OFFLINE 通道底下每個 Payment Account 的交易紀錄，也是建立三種手動單的入口。其他通道的帳號不在這一頁出現。

Summary by AccountNEW：把目前篩選條件下的交易紀錄依帳號加總，每個帳號一列；條件範圍內沒有交易的帳號不列出。欄位共 17 欄：Account Code、Account Group、Bank Name、Account Name、Account No、Status、Balance（這七欄是帳號目前的資料，不隨日期區間改變），接著十個金額欄。Deposit、Withdraw、Internal Out、Internal In、External Out 是同名類型的金額合計；Bank Fee、Interest 是該類別調整的金額合計；Unclaimed、Loan、Other Adjust 是淨額（ADJUST IN 減 ADJUST OUT，可以是負數），其中 Other Adjust 是其餘所有類別的調整。金額皆為 DECIMAL(18,2) 的加總，由後端計算。依 Account Group、Account Code 排序（沒有分組的帳號排在最後，分組顯示 -），每頁 10 筆；表格最下面一列 Total 是全部列（不只本頁）的合計。點 Account Name 切回 Transactions 並以該帳號篩選。已刪除的帳號若在條件範圍內有交易，仍列出一列：帳號資料用交易當下的值，Status、Balance 顯示 -，戶名不是連結。
一列是一筆會改變帳號餘額的交易，建立後不可修改或刪除。依 Created Time 由新到舊排列。Account Name 是連結，點了把篩選切到該帳號。
Type 共七種：
・DEPOSIT（＋）：玩家存款核准時，收款帳號產生一筆。只有收款帳號是 BANK-OFFLINE 帳號的存款才會產生。
・WITHDRAW（－）：Finance Approval 以 BANK-OFFLINE、指定帳號核准出款時，該帳號產生一筆。選 Not specified、以其他通道核准、經 Force Approve 完成的出款不會產生，也不扣任何帳號的餘額；這些出款由財務事後用 Adjust Balance（類別 Unrecorded Withdrawal）補扣。
・INTERNAL OUT（－）、INTERNAL IN（＋）：一張內部轉帳單產生兩筆，轉出帳號一筆、轉入帳號一筆，金額相同、Reference No 相同、同時生效。
・EXTERNAL OUT（－）：轉到外部。
・ADJUST IN（＋）、ADJUST OUT（－）：調整餘額，含用 Set balance to 登記帳號實際金額時產生的差額。
欄位：Amount 恆為正數，畫面以 ＋／－ 表示方向；Balance Before／Balance After 是這筆交易前後該帳號的餘額；金額皆為 DECIMAL(18,2)。Reference No：DEPOSIT／WITHDRAW 是存款單號／出款單號，手動單是系統產生的單號。Details：把手動單填寫的內容併成一欄顯示，各段以「·」分隔，沒有填的段落不顯示。INTERNAL OUT＝To: 對方帳號＋Remark；INTERNAL IN＝From: 對方帳號＋Remark；EXTERNAL OUT＝To: 對方銀行 / 戶名 / 帳號＋Purpose；ADJUST IN／ADJUST OUT＝Category＋Remark；DEPOSIT／WITHDRAW＝Player: 玩家帳號（存款單、出款單上的 Username）。資料上玩家帳號、對方帳號、Category、Remark（或 Purpose）是四個獨立欄位，匯出 CSV 時分成四欄。Created By：建單人；DEPOSIT／WITHDRAW 是核准的人。
帳號欄位（代碼、銀行、戶名、帳號號碼）顯示交易當下的資料，之後在 3.7 修改帳號不影響已有的紀錄。例外是 Account GroupNEW：顯示帳號目前的分組，與篩選條件一致；帳號改了分組，舊紀錄也跟著顯示新的分組；已刪除的帳號、沒有分組的帳號顯示 -。戶名、帳號號碼、錢包地址、對方帳號屬敏感資料，AES-256 加密存放。
Total In／Total Out：目前篩選條件下全部紀錄（不只本頁）的轉入合計與轉出合計。
金額上限：單筆金額、餘額、今日存款累計、今日出款累計的上限都是 9999999999999999.99。任何交易會讓某個帳號的餘額或今日累計超過上限時，整筆不生效（內部轉帳兩筆都不產生）。核准出款與手動單回 409 AMOUNT_LIMIT_EXCEEDED；玩家存款核准則是核准失敗、存款單狀態不變，依既有的核准失敗方式回應，不新增錯誤碼。手動單的表單顯示 The amount exceeds the maximum value allowed for this account.（mockup 不呈現）。前端＋後端都要擋。
手動單單號：系統產生、全系統不重複，前綴 IT（Internal Transfer）、ET（External Transfer）、AJ（Adjust Balance）。
同一交易內完成：每一筆交易紀錄與帳號餘額的變動要同時生效或同時不生效；內部轉帳的兩筆也是。金流請求帶 Idempotency-Key，重送不重複入帳。
資料範圍：只列出登入者所屬代理的帳號的紀錄，與 3.7 列表相同。

名詞與欄位來源

本頁是給 RD 的參考說明，不屬於正式 BO 畫面。
1. 名詞
名詞是什麼用途
Meta Pixel裝在前台網頁的 Meta 追蹤程式碼從瀏覽器把事件送給 Meta
CAPI（Conversions API）後端呼叫的 Meta API從伺服器把事件送給 Meta
sender後端送出 CAPI 事件的程式入款成功、註冊成功時組 payload 並送出
fbclid玩家點 Facebook 廣告時，Meta 加在網址上的參數，例如 ?fbclid=IwAR2xYz代表一次廣告點擊
fbc由 fbclid 組成的字串，格式 fb.1.<建立毫秒>.<fbclid>Meta 用它把轉換對回廣告點擊
fbpPixel 寫在 _fbp cookie 的值，格式 fb.1.<建立毫秒>.<隨機數>代表一個瀏覽器
_fbc、_fbp cookiePixel 寫在瀏覽器的兩個 cookie前端取得 fbc、fbp 的來源
external_id（雜湊 ID）玩家內部 ID 經 SHA-256 雜湊後的小寫 16 進位字串讓 Meta 把同一位玩家的事件串在一起
client_ip_address玩家的 IPMeta 用它輔助比對玩家
client_user_agent玩家瀏覽器的 User-AgentMeta 用它輔助比對玩家
event_source_url事件發生時玩家所在頁面的完整網址Meta 用它判斷事件發生的頁面。本案沒有值時，sender 不帶這個欄位，事件照送
event_id事件的唯一編號Pixel 與 CAPI 送同一事件時，Meta 用它去重
action_source事件發生的來源Meta 用它區分網站、App 等來源。本案開關 Enable 時，sender 送 website
比對參數fbc、fbp、client_ip_address、client_user_agent 四個欄位的合稱sender 放進 user_data
meta_match前端存在 localStorage 的 key保存 fbc、fbp，期限 7 天

2.2 前端送給後端的 request 欄位

欄位型別必填怎麼取得哪些 API 帶負責端
meta_fbcstring，長度上限 500否取自 meta_match 的 fbc。fbc 依下方表 A 決定註冊、登入、發起存款前端（Web/H5）
meta_fbpstring，長度上限 255否取自 meta_match 的 fbp。fbp 依下方表 B 決定。前端不自行產生 fbp註冊、登入、發起存款前端（Web/H5）
meta_event_source_urlstring，長度上限 2048否玩家當下所在頁面的完整網址註冊、發起存款。登入不帶前端（Web/H5）
前端組 request 前檢查 ts。已過期的參數，前端不帶。
meta_match 沒有某個值時，前端不帶該欄位，不送空字串。
欄位缺少時，後端照常處理註冊、登入、存款，不回錯誤。
欄位長度等於上限時，後端照常保存。
欄位超過長度上限時，後端把該欄位當成沒帶。
欄位超過長度上限時，後端不保存該值。
欄位超過長度上限時，sender 不使用該值。
欄位超過長度上限時，後端照常處理請求，不回錯誤。
前端不送 IP 與 User-Agent。
註冊成功與登入成功時，後端從 request 讀取 IP 與 User-Agent，覆蓋玩家資料的 client_ip_address、client_user_agent。
發起存款時，後端從 request 讀取 IP 與 User-Agent，記在該筆存款單上。
註冊成功與登入成功時，request 的 meta_fbc 有值，後端用它覆蓋玩家資料的 fbc；meta_fbc 沒有值時，後端保留玩家資料的 fbc。
註冊成功與登入成功時，request 的 meta_fbp 有值，後端用它覆蓋玩家資料的 fbp；meta_fbp 沒有值時，後端保留玩家資料的 fbp。

2.2.1 前端每次載入頁面時，meta_match 怎麼更新

前端用 localStorage 的 key meta_match 保存 fbc、fbp，每個值各有取得時間 ts。
未過期：ts 距今小於或等於 604,800,000 毫秒（7 天）。已過期：ts 距今大於 604,800,000 毫秒。
尾段：fbc 第三個 . 之後的字串。建立時間：fbc 第二個 . 與第三個 . 之間的 Unix 毫秒數。
網址的 fbclid 是空字串時，前端當成網址沒有 fbclid。
前端照原樣使用 fbclid，不改大小寫，除了 URL decode 不做其他處理。
前端不自行產生 fbp。
localStorage 無法讀寫時，前端把結果存在本頁記憶體。

2.3 後端回給前端的 response 欄位

欄位型別必填怎麼取得哪些 API 回傳前端用途
meta_capi_enabledboolean是後端查玩家所屬 Agent 的開關。Enable 時為 true，Deny 時為 false玩家資料、登入、註冊前端用它決定 Pixel 帶不帶 external_id。註冊時，前端也用它決定 Pixel CompleteRegistration 是否帶 eventID 去重
meta_external_idstring，64 字小寫 16 進位否後端把玩家內部 ID 做 SHA-256，輸出小寫 16 進位字串。開關 Deny 時不回傳玩家資料、登入、註冊Pixel 帶上與 CAPI 相同的 external_id。前端不自行雜湊
meta_registration_event_idstring，格式 reg_<玩家內部 ID>否後端組成 reg_<玩家內部 ID>。開關 Deny 時不回傳註冊當作 Pixel CompleteRegistration 的 eventID，與後端 CAPI 事件去重
3. 一筆存款的資料流
  1. 玩家點 Facebook 廣告進站，網址帶 fbclid。
  2. 前端照表 A、表 B 更新 meta_match。
  3. 玩家發起存款。前端帶 meta_fbc、meta_fbp、meta_event_source_url。
  4. 後端從 request 讀取 IP 與 User-Agent。
  5. 後端把 fbc、fbp、IP、User-Agent、event_source_url 記在存款單上。
  6. 入款成功。開關 Deny 時，sender 送出的事件與現況完全相同，流程結束。
  7. 開關 Enable 時，sender 照下表取值，加進 CAPI payload 後送出事件。
  8. 開關 Enable 時，Marketing Event Delivery Report 的 Details 顯示 sender 實際送出的新增欄位。sender 沒有帶的欄位，Details 不顯示。
  9. 開關 Enable 時，後端把 client_ip_address 加進遮罩清單。Details 把 client_ip_address 顯示為 ***。
